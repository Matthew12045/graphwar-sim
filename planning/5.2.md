## 2. Emission budget — SOLVE THIS FIRST

`parser.py` implements `PolishNotationFunction`. Output is PREFIX. A J-term
Gaussian sum is a nest of `+` J-deep, each term a fixed token block. This
collides with the character limit AND the M5.3 AST depth cap. It is a
feasibility constraint on the solver, not a post-processing concern.

Before implementing the LP:
1. Emit ONE Gaussian term with the M3 plain-decimal formatter. Measure its
   exact character cost, including the enclosing `+`.
2. J_max = floor((char_limit - affine_term_cost - safety) / per_term_cost).
   COMPUTE this. Do not guess it. Assert it in a test that reads the limit
   from GROUND_TRUTH/config so the test breaks if the limit changes.
3. Nest additions as a BALANCED tree wherever the grammar permits — depth
   log2(J) instead of J. Verify the parser accepts the balanced form and
   that it round-trips to the same values as left-linear nesting.
4. Plain-decimal only. Scientific notation corrupts the parser. Regression
   test, not a preference.

The Shared_core persona prompts already require "emit ONLY the bare
expression" — CCF output must satisfy that too, since HybridAgent returns
it verbatim. No wrapping text, no whitespace padding.

## 3. Basis

    phi_j(u) = exp(-(u - c_j)^2 / (2*sigma^2)),  c_j uniform on [0, u_T]
    PLUS phi_lin(u) = u  and  phi_const(u) = 1

The affine terms are FREE capacity: f'' = 0, so they do not enter the
curvature bound. They absorb the endpoint constraints instead of burning
Gaussian weight. Exclude them from ||w||_1 and from the s constraint; give
them a small separate penalty only to keep the string short.

Truncate phi_j at |u - c_j| > 6*sigma to keep the constraint matrix sparse
and avoid exp underflow. Truncation must apply IDENTICALLY to the LP and to
the emitted expression — a term dropped from one and kept in the other
invalidates the certificate.

## 4. Curvature bound (derivation goes in the docstring)

With t = (u - c_j)/sigma:

    phi_j''(u) = (1/sigma^2) * (t^2 - 1) * exp(-t^2/2)

g(t) = (t^2 - 1)*exp(-t^2/2) attains |g| = 1 at t = 0; the other critical
points t = +/-sqrt(3) give |g| = 2*e^-1.5 ~ 0.446. So
sup_u |phi_j''(u)| = 1/sigma^2, and:

    M = max|f''| <= sigma^-2 * ||w||_1 = sigma^-2 * s

That is the whole trick: M is bounded by a NORM of the decision variables,
so the required margin is LINEAR in them and lives inside the LP. No
fit-then-check, no fixed-point loop.

Unit test: sample random (w, sigma), compute max|f''| numerically on a dense
grid, assert <= sigma^-2 * ||w||_1.

## 5. Corridor — CELL-WISE, not pointwise

In `graphwar_sim/corridor.py`, shared with M5.1's sweep.

The interpolation bound controls deviation from the CHORD between samples.
A corridor defined only at sample points certifies nothing between them — a
terrain spike inside a cell defeats it.

Per cell k = [u_k, u_{k+1}]:
- Lcell_k = sup of lower obstacle bound over the WHOLE cell
- Hcell_k = inf of upper bound over the whole cell
- Terrain is a polyline: take exact extrema over the cell, do not sample.
- Teammate exclusion disks use SOLDIER_RADIUS from config.py, inflated by
  blast radius — the Shared_core prompts already forbid friendly fire, so
  the solver must enforce it, not hope for it.

Per sample: L_k = max(Lcell_{k-1}, Lcell_k), H_k = min(Hcell_{k-1}, Hcell_k)
(endpoints use their single adjacent cell).

Docstring justification: both chord endpoints lie in the cell interval, the
interval is convex so the chord lies inside it, and f deviates from the
chord by at most M*du^2/8. Margin at both endpoints certifies the
CONTINUOUS curve across the cell.

Corridor empty at any k -> return UNREACHABLE. Do not build an LP.

## 6. The linear program (fast path)

Variables: w in R^J, t in R^J, s, a, b, slack_k >= 0

    minimize   s + mu*(|a| + |b|) + lambda * sum_k slack_k
    subject to
      -t_j <= w_j <= t_j                          for all j
      sum_j t_j <= s                              (s >= ||w||_1)
      f(u_k) = sum_j w_j*phi_j(u_k) + a*u_k + b
      f(u_k) >= L_k + (du^2/(8*sigma^2))*s - slack_k
      f(u_k) <= H_k - (du^2/(8*sigma^2))*s + slack_k
      f(0)   = 0                                  (muzzle at soldier)
      f(u_T) = dy_T                               (target)

- lambda large enough that slack is used only when the hard problem is
  infeasible. Any solution with slack > 0 is UNCERTIFIED — never report it
  as proven. Slack buys a usable near-miss; it does not launder a failure.
- The target endpoint is exempt from the margin (destination, not obstacle).
  The sample immediately before it is NOT exempt.
- `scipy.optimize.linprog`, HiGHS. Do not hand-roll a simplex. Do NOT add
  cvxpy — `Implementation.py` used it, that file is superseded, and the dep
  is not worth carrying.

## 7. MILP overflow path

If the fast-path solution emits longer than the character limit or deeper
than the AST cap, re-solve with cardinality control:

    |w_j| <= B * z_j,  z_j binary,  sum_j z_j <= J_max

`scipy.optimize.milp` — HiGHS-backed, same solver stack, no new dependency.
B is a big-M bound derived from map height; document the derivation.

- MILP is the FALLBACK, not the default. Log how often it fires; if it
  fires on most invocations, J or the sigma ladder is misconfigured.
- Set a MILP time budget. On timeout, fall back to the LP solution with the
  smallest-magnitude terms pruned and RE-VERIFIED per section 9. If that
  still overflows, emit BASIS_INFEASIBLE and escalate.

## 8. Branch selection — specified, not inherited

When F_k is a union of disjoint intervals, the corridor has branches
(over vs. under an obstacle). There is NO prior art in the repo for this —
`Implementation.py` has none. Specify it here:

- Build a DAG: node = (sample index k, interval index within F_k). Edge
  between consecutive samples if the intervals are reachable under the
  slope cap S from M5.1.
- Edge cost = a slope-change proxy (curvature demand), so the cheapest path
  is the one most likely to admit a small ||w||_1.
- Shortest path (Dijkstra) gives the first branch to try. Take the K best
  paths; K is TUNABLE, default small. Solve the LP per branch, keep the
  best certified result.
- If no branch certifies, report the branch that got closest, with its
  binding constraint. That is the escalation reason.

## 9. Sigma ladder, sparsity, pruning, re-verification

- Sweep sigma coarse -> fine. First feasible sigma wins; log which one.
  Small sigma = more curvature capacity, weaker certificate. The ladder
  makes that tradeoff explicit instead of tuned.
- J default tied to u_T/sigma so basis resolution tracks shot length,
  capped at J_max from section 2.
- LP vertex solutions are sparse — that is the point. Sparsity shortens the
  string AND tightens M simultaneously. The old fixed_grid rung failed
  because least-squares gives dense weights, long strings, loose bound.
  Same basis, wrong objective.

After solving:
1. Prune |w_j| < epsilon.
2. RE-VERIFY. Pruning lowers ||w||_1 (smaller margin, good) but MOVES the
   curve (bad). Recompute f at all samples with pruned weights and the
   recomputed s; re-check every corridor constraint.
3. On failure, restore the pruned terms and emit unpruned.
Never emit a pruned expression that has not been re-verified.

## 10. Outcomes — machine-readable, no bare failures

    CERTIFIED         LP feasible, slack = 0. Clearance is PROVEN.
    UNCERTIFIED       feasible only with slack > 0. Usable, not proven.
    EMIT_OVERFLOW     certified but unemittable within char/depth limits
                      after MILP. Distinct from BASIS_INFEASIBLE — the math
                      worked, the grammar did not. Report separately.
    BASIS_INFEASIBLE  infeasible at every sigma, every branch.
    UNREACHABLE       corridor empty (M5.1). Not a solver failure.

Escalation carries the reason: which bound, which u_k, which sigma, which
branch. "Rung failed" is not a log line.
